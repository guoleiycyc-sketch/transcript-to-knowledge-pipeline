## 说话人映射（最高风险！）

### 反面案例：08-09 场我连续判错两次

**真实情况**：

| ASR 标签 | 我两次都判成 | 实际 |
|---|---|---|
| 🟢 A | A ✅ | A |
| 🟣 说话人2 | B ✅（用户首次确认） | B |
| 🔵 说话人3 | **D** ❌ | **C**（主导商业规划） |
| 第四人 | C（"发言被并入"）❌ | D（发言少，未识别） |

**为什么错**：

1. 第一次：A在 `[01:28:08]` 直接称呼说话人3 为"D"——我以为说话人3 = D
2. 第二次：基于这次错误，把C当成"发言被并入的隐形人"
3. **真相**：说话人3 是C（主导商业规划、做视频号、润商会合伙人、公司年营收一亿）；A叫的"D"是C的称呼（可能被叫D/被 ASR 同音误听/旧称）
4. **D是另一个人**，在场但发言不多

### 方法论：角色指纹 + 时间线核对 + 用户二次确认

#### Step 1：列每个 ASR 标签的「角色指纹」

| 指纹维度 | 提取什么 |
|---|---|
| 主导什么内容 | 技术？商业规划？主持？咨询？ |
| 自述身份 | "我公司""我们公司""我跟刘志伟""我搞了视频号" |
| 被他人称呼 | 谁叫你？叫你什么？ |
| 第一次出现时间 | `[HH:MM:SS]` 上车 / 插话 / 加入 |
| 语用风格 | 短接话 vs 长论证 vs 提问推动 |

#### Step 2：交叉校验（必须做）

| 校验项 | 怎么查 |
|---|---|
| **主导 vs 标签** | 用户说"主导 X 的是 Y" → Y 对应的 ASR 标签 = X 的主导者 |
| **时间线一致性** | 如果 X 在 `[00:20:07]` 才到场，则 `[00:20:07]` 之前被 ASR 标为 X 标签的回合**可能不是 X**（或是 X 早就在场但 ASR 误标） |
| **称呼 ≠ 身份** | A 被 B 叫"D"≠ A 就是D。称呼可能是绰号 / 旧称 / 同音误听 |
| **自述内容 vs 指纹** | 说话人3 自述"我跟刘志伟是润商会合伙人"→ 润商会合伙人身份锁定 |

#### Step 3：用户二次确认（绝不能省）

**哪怕第一步感觉很清楚，也要让用户确认**。本次示例对话：

> **AI**：转写里"说话人2（🟣，全场技术核心：讲服务器成本/token/K3/agent部署，有海外工作背景）"对应哪位参与人？
> **用户**：说话人2 = B
>
> （数小时后，用户主动补充）
>
> **用户**：主导做商业规划的是C，再次结合原文分析
> **AI**：重新分析后发现说话人3 是C，主导商业规划，做视频号…
> **用户**：做视频号、润商会的是C，主导商业规划的也是C，D说话不多

**要点**：

1. 第一次确认时不要假设其他说话人的身份——只问最不确定的那个
2. 用户可能第一次答得不完全准确（信息有限/记不清），必须**保留后续追问 / 二次确认的余地**
3. 一旦发现新矛盾（如"主导商业规划的 X"对不上当前映射），立即回原文复核，而不是猜测

#### Step 4：识别身份存疑的发言（不要硬拆）

有些回合确实无法判断是谁说的（ASR 合并 + 无音频）：

- **不要硬拆** —— 保留原归属，在附录"说话人说明"里标注
- 不要为了"还原得漂亮"而臆造身份
- 把无法确定的回合明确划入"未识别"

### 改名映射时的"称呼与标签不一致"处理

修正映射后，原话里的称呼词（被叫的称呼）**必须保留**（金句原则：原话一字不改）。但头部必须显式说明：

```markdown
- 🟢 **A** = …
- 🟣 **说话人2 → B** = …
- 🔵 **说话人3 → C** = …[00:20:07] 到场加入；本场商业规划主导者…
- **D** = 在场参与，发言不多，ASR 未单独识别。注意：原文中A、B 多次以"D"相称，该称呼多指向C（说话人3）；个别处（如 [02:07:38]、[02:35:00] C自述团队"咨询由D、郭老师提供"）指真正的D作为咨询顾问之一。原话中"D"称呼词一律保留不改，由本说明区分。
```

读者看 `**【C】** [01:28:08]` 但话里说"D巨牛逼"——结合头部说明，立刻理解"D"是A对C的称呼。

## 时间线核对（必查）

| 时间线冲突类型 | 例子 | 处理 |
|---|---|---|
| X 在 [00:20:07] 才到场，但 [00:15:32] 有人叫 X 发言 | 误识别 → 撤销 | 恢复原 ASR 归属，标注"口误/存疑" |
| X 自述"我们公司一亿"但 Y 才是那个公司的人 | 矛盾 → 查上下文 | 看完整段判断 |
| 同一句话两人轮换太快，ASR 标错 | 错位 | 逐字比对原文转写 |

**任何说话人改动，都要重新跑时间线核对**。

## 标签结构异常类型（2026-08~09 实战累积）

ASR 标签的问题不止「映射到谁」，还有**结构性异常**——标签与真人不呈一一对应。五种已见类型，遇见先对号入座再动手：

### 类型一：多人压一标签，按时段切分

一个 ASR 标签在不同时段其实是不同的人。案例：08-18 WorkBuddy 参访场（5+ 人压成两个标签）、8-30 客户戊场（8 标签吞 10 真人：说话人4 吞刘志伟+石墨烯者、说话人6 吞洪波+一伟）、8-27 分享会（🟢 开场自介段=17 人轮流、[00:37:51] 起=Z7）。

**判据**：同一标签的发言内容/口吻跨时段断裂 + 外部交叉源（会议室录制稿自带发言人 1-8）或自介段锚点句。
**处理**：按时段拆分、各标【姓名】，头部写明切分依据；多人自介段可合并为「与会者轮流自介」。

### 类型二：双身份标签

同一标签中段与压轴是两个人。案例：8-27 场 🟡 中段=职位预测系统创业者、压轴=卢老师（按外部版发言人锚点归位）。

**判据**：内容指纹（业务自述）在段内突变 + 交叉源锚点。
**处理**：按内容指纹归位、各自标注，时间线写进头部。

### 类型三：视频原声误归

外放视频（视频号/演示片）的声音被 ASR 全归到在场者名下。案例：9-03 场 [01:30:25]-[01:32:39] 视频号 2 倍速播放段全归「A」。

**判据**：①在场者插话提示（B「两倍速」）；②内容第一人称自述与在场者立场相反；③真声间隙有该人插话。
**处理**：改标【视频原声】，**不计入该人发言量与回合比**（影响 05 人物卡占比）。

### 类型四：会后 AI 语音混录

录音结束后的智能体测试语音被当作正常说话人。案例：8-17 缔约场说话人3 末尾两段「羞于谈钱」实为合作方A智能体会后混录。

**判据**：内容与会议主题脱节 + 集中在末尾 + 表达风格机械。
**处理**：移入附录（如附录 E），正文标注剔除依据。

### 类型五：旁听者 / 英文场无标签

录音者本人旁听未发言时，ASR 不给独立标签（9-03 某英文场次：A被双方反复呼唤但全程无标签）；英文场（ASR 英文转写破碎）同样可能出现说话人缺失。

**处理**：旁听者身份写进头部说明（「A旁听，被提及未发言」）；英文场清洗走 02 的边缘类型规范（机械复制段剔除、不臆造修复）。

## 第三种陷阱：转写标签 ≠ 本人（账号名陷阱）

**陷阱描述**：转写标签看起来是完整姓名（「X」），但其实是某位参会者的**腾讯会议账号名**——得到大脑按参会账号名标注转写，不是按真实身份。

**首次发现**：2026-08-19 客户丁场——F（F）用腾讯会议账号「X」入会，整场 docx 标签全为「X」，但与会者都叫她「F/F/郭老师」，从未叫「X」。

**检测方法**：

1. 头部映射块写「docx「X」218 回合」但本人从未自称过此名
2. 转写标签形式是完整姓名，但与会者当面都不叫此名
3. **跨场 grep**：在 `<录音项目根>` 下 `grep -rn X` ——无任何其他匹配 → 高概率是账号名
4. 反之，若「X」在其他录音/纪要中也出现 → 多半是真人本名，按普通映射处理

**修复方法**：

- 与 P1（称呼≠身份）/P11（用户首次确认不绝对）同思路
- 头部映射块显式标注：「转写标签「X」= 该参会者的腾讯会议账号名」（如「**「X」是她使用的腾讯会议账号名**（用户 2026-08-19 确认）」）
- 正文回合全部改标真实姓名，文件名与账号名语境的「X」保留原样（金句原则）

**详见** `references/08-cross-session-sync.md` 第二点。
