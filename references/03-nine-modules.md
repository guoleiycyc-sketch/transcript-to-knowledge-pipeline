# 阶段 ③ 九模块产出

完整格式模板见 [`format-templates.md`](./format-templates.md)（已内联至本 skill）。

本文件只补 9 个模块的**工程化要点**——容易写错、容易漏的字段。

---

## ⚠️ v2 模块规范（2026-08-19 三方评审后新增，逐条必守）

> 背景：20 场实测发现——03/08 同题率 50%、金句在 01/02/08 三处重复、04 混三种词条、跨场连线双头维护。三方评审（知识管理/咨询/定性研究）一致结论：**重复的根因是跨层复制正文而非存引用**。以下判据为根治方案。

### 1. 新增 00_执行摘要.md（每场必写，最先写）

BLUF 四段式，≤200 字，写给"要转发的读者"（团队/Kelly/客户）：

```markdown
# <场次名> · 执行摘要

**局势**：一两句（谁、为什么谈、什么背景下）
**本场决策/结论**：3-5 条（最重要的放前面）
**待办**：带 Owner（与 09 联动）
**风险/未决**：身份存疑、待确认项、外部依赖
```

### 2. 02 只做描述性编码，禁写"法则"

02 的职能=open/axial coding：时段、参与者、何条件下说了何话、时序因果链。
- **禁止**在 02 写"这提炼出一条 XX 法则/启示"级命题（那是 08 的职能）
- 每段末尾加 `## 段结论` 一行字（喂 08/09 用）
- **金句字段=引用制**：`> [段内时间戳] 说话人 （15 字提示…）`——正文唯一真身在 01 的回合里，02 不复制全文

### 3. 03/08 互斥判据（同题 50% 的根治）

| | 03 方法论 | 08 洞察卡 |
|---|---|---|
| 判据 | 能写成"**遇 X 情境→执行 Y 步骤**" | **反直觉判断**，值得找反例 |
| 必有 | 定义+出处+怎么用（操作步骤） | 核心+证据+启示+**反方（必填）** |
| 禁止 | 出现"反方/边界/张力" | 出现操作步骤 |
| 口诀 | — | **删掉引文就站不住的是 02，敢下断言值得找反例的才是 08** |

- 03 只收**本场新增**的方法论；已有方法论的变体只登记一行变化（"本场 X 条方法论中 N 条为总库已有变体"）
- 同一内容两个视角都值得留时：03 写操作、08 写张力，两处互引，不重复写定义

### 4. 04 瘦身为纯外部名词索引

只留"不自解释就读不懂的名词"（产品名/行业黑话/组织代号）。
- 人名词条：一句话+`→ 详见 05` 指针
- 方法论词条：`→ 详见 03` 指针
- 本场不新增外部名词时，04 可以只有 3-5 条

### 5. 05 加"较上场的变化"字段

单场快照保留，但每人多一行：`**较上场变化**：<一句话>`——纵向弧线归全局干系人档案。

### 6. 07 只画本场结构

跨场连线、"本场卡 X=上场卡 Y"类内容**全部移出 07**，归 README 跨场表一处维护（README 是唯一跨场维护点，全局母题总图是第二层）。

### 7. 09 轻量化+行动闭环

- 凡本场产生待办即出 09（不限咨询/诊断类）；圆桌/闲聊无待办则不出
- 开头强制一节 `## 上期行动回顾`（从全局决策日志拉取本场相关人的未闭环项）
- 行动条目增加**状态列**（open/done/deferred），不只 Owner

### 8. 分档（写 00 前先定档）

三问：①决策密度（改变在途决策？）②外部受众（发团队/客户？）③资产含量（可复用方法/金句多寡？）

| 档 | 适用 | 模块 |
|---|---|---|
| 重装 | 咨询/谈判/战略 | 00+02+08+09 全套+01 |
| 标准 | 参访/训后/产品 | 00+轻量 02+01，喂全局库 |
| 轻档 | 信息/闲聊 | 01+00 摘要卡，只自动喂全局库 |

## 9 个模块一览

```
<场次目录>/
├── 01_清洗稿.md          ← 阶段 ② 产出（素材层，不进 HTML）
├── 02_主题整理/第N段_xxx.md  ← 6–10 段，按议题切
├── 03_方法论清单.md      ← 可复用思维工具
├── 04_术语表.md          ← 一句话解释 + 出处
├── 05_人物角色卡.md      ← ## 人名 + **背景与立场**： + 约 XX%
├── 06_关键数据速查.md    ← 表格，可排序
├── 07_议题关联地图.md    ← **母题**：+ ```ASCII 图（必须代码块）
├── 08_洞察卡片.md        ← 非显而易见，**反方必填**
└── 09_战略诊断与行动清单.md  ← 仅咨询/诊断类
```

## 02 主题整理（每段一个文件）

**首行格式硬要求**：`# 第N段 · 标题`（render_pack 从这里提取段标题，错了渲染会乱）

```markdown
# 第1段 · AI agent 定价分层

> 时段：01:17:00–01:43:00 ｜ 主导：郭志梁

## 摘要
2–4 句话概括。

## 详细分析
### 小节标题 1
…
### 小节标题 2
…

## 金句
> **【盛思维】** [00:18:45] 原话一字未改。
> **【王伟】** [00:07:23] 另一句原话。

## 原文节选
**【余一】** [00:14:18] 原话段落……
```

**要点**：
- 文件名 `第N段_主题.md`，N 决定渲染顺序
- `> 时段：…` 行被提取为副标题
- 金句和原文节选必须用 `**【姓名】** [ts] 内容` 格式（不然金句卡不可点击）

## 03 方法论清单

```markdown
# XX 方法论清单

## 1. 方法名
- 定义：一句话讲清楚这个工具是什么。
- 出处：段N [00:时间戳]
- 怎么用：什么场景下用它、具体怎么做。

## 2. 另一个方法名
…
```

**render_pack 识别关键**：`## N. 名称`（数字 + 点）—— 用来自动计数卡数。

**文末必加**：

```markdown
---

## 命中校验
| 卡 | 出处标注 | 清洗稿可命中 |
|---|---|---|
| 1 | 段2 [00:06:24] | L281 |
| 2 | 段5 [00:22:10] | L458 |
```

命中校验 = 校对每一张卡都能在清洗稿里找到对应行。

## 05 人物角色卡（render_pack 自动提取依赖）

```markdown
# 人物角色卡

## 王伟

**角色标签**：一线实践者 / 词元无限 CTO

**背景与立场**：做企业级 agent 基础设施，本场最坚定的乐观派。

展开：多句补充背景、立场、本场表现……

**进场时间**：05:45

**发言量占比**：约 30%

**本场作用**：定义者 + 反驳者，段2 给定义、段5 旗帜鲜明唱反调。

**代表发言**：
> [00:07:23] FDE 既要承担交付，又是产品迭代的前线。
```

**render_pack 靠这些标记自动提取**（**缺一不可**）：

- `## 人名`（人名紧跟 ##）
- `**背景与立场**：xxx`（一句话 tagline）
- `约 XX%`（画进度条用）

**代表发言格式**：可以用 `> [ts] 姓名 内容`（短格式）或 `**【姓名】** [ts] 内容`（长格式），render_pack 都认。

## 08 洞察卡片（最易翻车的地方）

```markdown
# 洞察卡片

> 从本场提炼的非显而易见、可独立分享的洞察。每张卡 = 核心 + 证据原话 + 启示 + 反方。

---

## 卡 1 · 模型越强，企业反而越需要人进现场

**核心**：一段话讲清这个反直觉规律。

**证据**：
> **【郑玄】** [01:48] 为什么模型越来越强，企业反而越来越需要人去进入现场？
> **【王伟】** [00:06:59] 在模型能力和业务交付之间，还有很长的一段路。

**启示**：怎么用这个规律。

**反方**：这个规律的边界、例外、或本场内的对立观点。

---

## 卡 2 · 标题
…

---

## 洞察地图
\`\`\`
ASCII 维度归类 + 贯穿线图
\`\`\`

**三条贯穿线**：
1. ……
```

**render_pack 识别关键**：

- 每张卡用 `## 卡 N · 标题`（"卡"字 + 数字 + 点）
- 字段头必须是 `**核心**：` `**证据**：` `**启示**：` `**反方**：`（或 `**边界/张力/张力**`）—— render_pack 靠这些识别字段
- `## 洞察地图` 必须存在，ASCII 图用 ``` ``` 包裹

### 反方必填（陷阱 P6）

**没有反方的洞察是断言，不是洞察。** 好的洞察往往是"正面成立，但有个边界/例外"。

每张卡的反方可以是：

- 本场内的对立观点
- 适用条件 / 边界
- 反例 / 风险条件

# 战略诊断与行动清单

……

## 二、现状诊断
| 维度 | 现状 | 卡点 |
|---|---|---|
| 业务 | …… | …… |

## 三、产品定位
## 四、技术路径
## 五、商业模式
## 六、团队

## 七、落地步骤（按优先级）
\`\`\`
P0  ……
P1  ……
\`\`\`

## 八、行动清单
| 优先级 | 行动 | Owner | 依据(段·时间戳) |
|---|---|---|---|
| P0 | 定人、绑股权 | 创始人 | 段9·[01:14:54] |
```

**只有"一方诊断、给建议、有行动"的对话才加**（咨询、商业诊断、转型讨论）。

**圆桌、直播、闲聊、纯访谈不加这个文件**——没有明确的"甲方"和"行动"，硬加会很别扭。
