# 发布前质量门禁

每场知识包交付前**必须**跑完检查，任意一项不过**不要交付**——回去修。

**一键跑全部**（推荐）：

```bash
bash <skill目录>/scripts/pipeline_check.sh <场次目录> [人名...]
```

pipeline_check 自动覆盖：场内 6 项 + 跨会话同步 1 项 + 三层收敛 1 项（人名自动从 01 头部映射提取，无需传参）。有 02/05/08 的场次另跑引文核证：

```bash
python3 <skill目录>/scripts/verify_quotes.py <场次目录>   # 引文逐字+时间戳命中（硬伤 exit 1）+ 反方空洞警告
```

以下是各检查项的手工版（理解检查逻辑用；日常直接跑脚本）：

## 检查 1：说话人一致性（最高优先级）

```bash
cd "<场次目录>"

# 1.1 残缺标签（漏 】）—— 应 = 0
grep -cE '^\*\*【[^】]*\*\* \[' 01_清洗稿.md

# 1.2 各说话人回合数 —— 应与映射一致（按本场人物替换人名）
for p in 人名1 人名2 人名3; do
  echo "$p: $(grep -cE "^\*\*【$p】\*\* \[" 01_清洗稿.md)"
done

# 1.3 残留未替换的 ASR 标签（如"说话人2"）—— 正文应 = 0
grep -cE '^\*\*【说话人' 01_清洗稿.md
```

**自查**：主导角色 = 回合数最多的人之一？各说话人指纹与头部映射声明一致？时间线无矛盾（到场前无该人回合）？

## 检查 2：ASR 残留

```bash
# 2.1 已知 ASR 错字残留（按本场对照表实际条目构造模式）—— 应 = 0
grep -cE "<已知错字1>|<已知错字2>" 01_清洗稿.md

# 2.2 [ASR/存疑] 项数（合理即可；过多说明清得不够）
grep -c "\[ASR/存疑\]" 01_清洗稿.md
```

**对照表与正文必须一致**：表里有 `[ASR/存疑]` 的项，正文里也标注；不在表里的常见错字不应出现在正文。

## 检查 3：金句格式（最容易出 bug）

```bash
# 3.1 残缺格式 —— 应 = 0
grep -cE '^\*\*【[^】]*\*\* \[' 01_清洗稿.md

# 3.2 完整格式计数（应 > 0；时间戳 HH:MM:SS 或 MM:SS）
grep -cE '\*\*【[^】]+】\*\* \[[0-9]{2}:[0-9]{2}(:[0-9]{2})?\]' 01_清洗稿.md

# 3.3 附录 B 金句速查（应 = 6-8 条，编号 + **【...】** [ts]）
grep -cE "^[0-9]+\. \*\*【" 01_清洗稿.md

# 3.4 锚点残留 —— 应 = 0
grep -c "APPEND_MARKER" 01_清洗稿.md
```

## 检查 4：结构完整性

```bash
# 4.1 必备文件存在（按本场档位调整）
for f in 00_执行摘要.md 01_清洗稿.md 02_主题整理 03_方法论清单.md 04_术语表.md \
         05_人物角色卡.md 06_关键数据速查.md 07_议题关联地图.md \
         08_洞察卡片.md README.md; do
  [ -e "$f" ] && echo "OK $f" || echo "MISSING $f"
done

# 4.2 02 段文件名连续、段标题首行格式
ls 02_主题整理/ | grep -E '^第[0-9]+段'
grep -E '^# 第[0-9]+段 · ' 02_主题整理/*.md | head -20

# 4.3 洞察卡有反方（数量应=卡数）
grep -c "^\*\*反方" 08_洞察卡片.md

# 4.4 议题地图有母题 + 代码块
grep -cE '^\*\*母题\*\*' 07_议题关联地图.md   # 应 ≥1
```

## 检查 5：HTML 渲染

```bash
python3 <skill目录>/scripts/render_pack.py "<场次目录>" 2>&1 | tee /tmp/render.log

# 5.1 生成成功（文件名=场次目录名）
[ -f "<场次目录名>.html" ] && echo "OK $(wc -c < <场次目录名>.html) bytes"

# 5.2 自包含（无外部 CDN）—— 应无输出
grep -E "https?://[^\"' )]+\.(js|css)" "<场次目录名>.html" | head
```

浏览器实测（不可自动化）：左侧导航段全显、①摘要卡、②速览行=段数、金句点击复制、表格排序、深浅主题。渲染自检（锚点有效性/②层字数/四类回归）由 render_pack 末尾自动跑。

## 检查 6：跨场呼应 + README 完整性

> 交付给外部客户/团队时，另跑**忠实度审计**作为「AI 改了什么」凭证：
> `python3 <skill目录>/scripts/diff_report.py <原稿.md> <场次目录>`（回合合并比/字符比/订正清单/结构自检）。

```bash
# 6.1 README 必备段
grep -E "^## 怎么看|^## 文件说明|^## 已知瑕疵|^## 与同体系" README.md

# 6.2 README 已知瑕疵列出 ASR 存疑项
grep -c "\[ASR/存疑\]" README.md

# 6.3 原始转写稿仍在原位置（清洗不动它）
ls -la "<原始逐字稿文件>"
```

## 检查 7：跨会话同步

见 `references/07-multi-session-kb.md`（主题 README 链表、总览 HTML、来源索引、人物映射记录）。pipeline_check 已内置链接校验。

## 检查 8：三层收敛

00_执行摘要存在与字数达标、02 段结论覆盖率——pipeline_check 已内置。

## 检查失败的回退指南

| 失败检查 | 回退到哪一阶段 |
|---|---|
| 检查 1（说话人） | 阶段 ① |
| 检查 2（ASR） | 阶段 ② |
| 检查 3（金句格式） | 阶段 ②（写漏 `】`）或 ③（字段头错） |
| 检查 4（结构） | 阶段 ③ |
| 检查 5（HTML） | 阶段 ③（标记错）或 ④（渲染器） |
| 检查 6（README） | 阶段 ⑤ |

**绝不跳过检查。绝不"先发了再说"。**

## 收尾三问（每次交付前强制过一遍）

1. **新坑入 06**：本场遇到的新问题，当天写进 `references/06-pitfalls.md`（先 `grep '^## P'` 看最大编号再顺延，防撞号），勿拖
2. **渲染自检 ✓**：render_pack 末尾自检输出确认无告警
3. **增量同步**：该做的多场次同步（atoms/索引/README 链表，见 references/07）做完了吗

## 执行层提醒（脚本查不出来的）

- **"用户确认过"≠"正确"**：用户首次回答可能基于不完整信息。发现新矛盾立即回原文复核，不猜测也不忽略
- **写完立刻 grep**：不要"写完觉得对了"——格式类 bug 只有 grep 能抓
- **大文件分块写**：Write 超长静默截断无报错，收尾必 `wc -l` 对比预期
- **坑库持续累积**：`references/06-pitfalls.md` 是活文档，每场新坑当天入库
