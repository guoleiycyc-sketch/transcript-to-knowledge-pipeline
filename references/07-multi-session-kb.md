# 多场次知识库（场次完成后的跨场同步）

> **为什么需要这个文件**：质量门禁只覆盖单场产物。多场次项目的实际返工往往不在场内，而在**场与场之间、场与记忆之间**。本文件把这些同步点集中成可执行清单。
>
> **何时读取**：阶段 ⑤（README + 跨场呼应）读一遍；做身份订正后必读——订正会跨文件扩散。

适用前提：你的项目按 `<场次名>_YYYY-MM-DD/` 组织多场产物（本管线的默认结构）。单场使用可跳过。

---

## 一、身份订正的波及清单

**陷阱**：身份订正看起来是局部动作（头部映射改一下）。实际上一处订正会扩散到 8 个位置，遗漏即场次间人物链条断裂、知识包互相打架。

**波及 8 点**（由近到远）：

1. **01_清洗稿.md**：头部映射块、对照表原词/还原列、正文回合标签、附录 C/D
2. **02_主题整理/** 全部 `第N段_*.md`：段内人名、**文件名**（如段标题含旧名）
3. **03_方法论清单.md**：引用说话人处
4. **04_术语表.md**：若人名作为术语条目（`### 人名`），重命名整个块
5. **05_人物角色卡.md**：人物卡标题、代表发言标签
6. **06_关键数据速查.md**：表格「说话人·[时间戳]」列
7. **07/08/09**：证据原话、行动清单 Owner
8. **场次 README.md**：金句速查、已知瑕疵、跨场呼应

**波及检查命令**（订正后必跑）：

```bash
cd "<场次目录>"
grep -rn "旧名" --include="*.md" . | grep -v "曾作\|原文\|疑\|注记"   # 应为空
bash <skill目录>/scripts/pipeline_check.sh .                          # 一键含人名一致性
```

## 二、双源场次的常见差异点

双源骨架见 `references/02`。常见组合的经验差异：

| 组合 | 典型偏移 | 差异点 |
|---|---|---|
| 会议平台全程导出 + 手机端转写 | ≈ 2 分钟（主源在前） | 主源有接通段/纪要元数据；交叉源有漏字 |
| 会议全程 + 单方手机录音 | ≈ 0-5 分钟 | 同上 |
| 同一场两段录音 | 0 | 内容一致但标题不同（防重复入库，见坑库 P19） |

## 三、下游同步清单（场次完成后的 6 处更新）

README 完成后逐处同步，遗漏任何一处都会让跨场叙事断裂：

| 同步点 | 位置 | 更新内容 | 漏了的风险 |
|---|---|---|---|
| 1. 场次 README | `<场次目录>/README.md` | 已知瑕疵/金句速查/跨场呼应 | 本场不可检索 |
| 2. 主题总 README | `<主题目录>/README.md` | 链表追加新场次 | 主题目录断裂 |
| 3. 总览 HTML | `<主题目录>/` 的总览页 | 链表章节、相对链接 | 链接 404，总览停在旧场次 |
| 4. 来源索引 | 转写来源目录的 `_索引.md` | 状态列改「已清洗→场次目录」 | 总索引误导 |
| 5. 人物映射记录 | 项目的词表/干系人档案 | 新人物/新 ASR 变体/新陷阱 | 下次清洗重蹈覆辙 |
| 6. 进度记录 | 项目进度笔记 | 新场次摘要 | 跨会话失去全局视角 |
| 7. ASR 词表 | `<项目根>/_词表.md`（`init_project.py` 生成） | 跨场可复用的新订正回填 | 下场重踩同款错字 |

**项目骨架初始化**：新项目一条命令生成标准三件套（`pipeline.config.json` 管线配置 + `_词表.md` 词表 + `录音来源/_索引.md` 来源索引）：

```bash
python3 <skill目录>/scripts/init_project.py <项目根> [--delegation]
```

幂等（已存在跳过不覆盖）。本表其余落点若与项目实际结构不同，以项目 CLAUDE.md 的约定为准。

**pipeline.config.json 的通用键**（extract_atoms / render_views / pipeline_check 均读取，已有项目可按需补）：`paths.atoms`（原子库位置，默认 `_全局资产/atoms.jsonl`）、`paths.views_dir`（视图目录，默认 `_全局资产`）、`skip_dirs`（递归扫描跳过的项目目录，追加在通用默认集上）、`old_names`（身份订正过的旧名数组——检查 2 的残留检测名单）。**个人项目的旧名/目录约定属项目数据，写在自己的 config 里，不进 skill**。

**同步检查**：

```bash
grep "<新场次目录名>" "<主题目录>/README.md"        # 链表应含新场次
# 总览 HTML 链接校验（pipeline_check 第 6 项自动做）
```

## 四、目录落位与原子入库判据

多场次项目通常按价值分层放产物。可参考的判据：

| 判据 | 落位 |
|---|---|
| 含 `02_主题整理/` 或 `08_洞察卡片.md`（深度加工场） | 成果目录（精洗层） |
| 仅 01（轻档） | 按月归档桶 |
| 轻档日后升级 | 整目录迁入成果层，索引回填 |

**原子入库线**：`extract_atoms.py` 以「目录含 `03_方法论清单.md`」为入库判据（递归扫描全项目树，嵌套场次目录自动发现）——不想入库的场就不写 03。同日多场有 sid 后缀机制防撞号（坑库 P30/P32，冲突会打告警，见告警即查）。

每场完成后：

```bash
python3 <skill目录>/scripts/extract_atoms.py <项目根>          # 抽取原子（方法论/洞察/引语/人物，带出处）
python3 <skill目录>/scripts/render_views.py <项目根> --view methods|quotes|share   # 刷新视图
# share = 脱敏分享版 HTML（过滤价格/健康级引语，可直接发团队/客户）
```

## 五、常用源的处理提示

- **会议平台导出 docx**：标签通常按账号实名（比手机端 ASR 可靠），双源结构中优先当主源。解析片段：

```python
import zipfile, re
z = zipfile.ZipFile("<docx 路径>")
xml = z.read('word/document.xml').decode('utf-8')
full = ''.join(re.findall(r'<w:t[^>]*>(.*?)</w:t>', xml, re.S))
# 格式多为「姓名(HH:MM:SS): 内容」连排，按时间戳切回合
```

- **专属转写工具的 API 拉取**：各平台 CLI/API 不同，按项目自备的拉取脚本/笔记执行（记录在项目层，不放本 skill）。

## 六、订正后落盘顺序（防漏 checklist）

```
身份订正确认（用户口头/文字）后：
  □ 跑「波及检查命令」
  □ 批量替换（含各文件标题、文件名）
  □ 头部映射块的「新名字段」+「账号名说明」
  □ 对照表（原词+还原双列）
  □ 跑全套 pipeline_check.sh
  □ 重渲染 HTML（render_pack.py）
  □ 同步人物映射记录 + 进度记录
  □ 同步主题总 README + 总览 HTML 链表
  □ 来源索引状态列
  □ grep -rn "旧名" --include="*.md" . | grep -v "曾作\|原文\|疑" → 应为空
```
