# 阶段 ② 清洗 + ASR 订正

## 目标

把 ASR 转写稿整理成**可读、可查、可作为后续模块素材源头**的清洗稿。

## 两种粒度（让用户选或自评）

| 粒度 | 回合数 | 适用 |
|---|---|---|
| **紧缩版** | 30–50 回合 | 用户要快速回顾；时间紧；后续可展开 |
| **逐回合还原版** | 150–700 回合 | 用户要忠实对话流；作为完整素材；后续做洞察卡片 |

默认**逐回合还原**（忠实优先于简洁）。

## 头部骨架：双源字段

> 多源场次（如会议平台全程导出 + 单方手机录音、两份不同平台转写）必须在头部写明双源，否则时间戳会坐错——两源偏移可达数分钟，错引就跳错位置。

```markdown
> 来源（主源）：<主源文件路径>（<平台/账号>，<YYYY-MM-DD HH:MM> 入会，<通话时长/段数>）
> 来源（交叉校验源）：<交叉源文件路径>（<平台/账号>，时间戳偏移 X 分钟，<差异点>）
> 时戳基线：所有清洗稿时间戳均按主源口径，引用交叉源时标注 [交叉源≈主源 ±X 分钟]
```

选主源的原则：优先标签可靠的一源（如按账号实名转写的会议平台导出），而非时间早的。

## 清洗原则（6 条，缺一不可）

1. **回合合并**：同一说话人连续的纯口水碎片合并为一个回合，保留首时间戳
2. **去口水**：删"嗯/啊/对对对/那个那个/就是就是/哈哈"等无意义重复；保留语气词当承载态度时
3. **补标点、理语序**，**不改原意、不改措辞**
4. **ASR 订正**：能确定的还原（登记对照表），不确定的标 `[ASR/存疑]`，**不臆造**
5. **正文回合一律不加粗**：`**xx**` 星号会炸掉 02/05/08 引文的逐字校验——强调用 `[标注]` 或叙述表达，加粗只属于 02-09 结构层
6. **分段读原文防脑补**：超长原文分段 Read 时，衔接段必须回查上一段末尾几行——凭上下文「应该是这样」补写出的回合是臆造原话，比错字严重一个量级

金句原话一字不改——这是最高的忠实原则。

## ⚠️ 致命陷阱：漏写右 `】`

`Write` 工具批量写回合格式时极易漏 `】`，写成：

```markdown
**【某人** [00:00:39] 你还要解释……
```

**正确格式必须是**：

```markdown
**【某人】** [00:00:39] 你还要解释……
```

漏 `】` → 渲染器识别不了 → **整篇金句格式失效** → HTML 里没有可点击金句卡。

### 检测（每段交付前必跑）

```bash
# 应输出 0
grep -cE '^\*\*【[^】]*\*\* \[' "<场次目录>/01_清洗稿.md"
```

### 修复（一行 sed，按本场人名改模式）

```bash
# macOS（sed -i ''）
sed -i '' -E 's/^\*\*【(人名1|人名2|人名3|人名4)\*\* /**【\1】** /' "<场次目录>/01_清洗稿.md"

# Linux（sed -i）
sed -i -E 's/^\*\*【(人名1|人名2|人名3|人名4)\*\* /**【\1】** /' "<场次目录>/01_清洗稿.md"
```

⚠️ 模式只匹配行首 `**【人名** `（缺 `】` 且缺第二个 `**`），不会误伤正确的 `**【人名】** `。修复后再跑一次检测确认 = 0。

## ⚠️ 致命陷阱：Write 超长截断

`Write` 一次写超大文件（> 5 万字节或含大量特殊字符）会被**静默**截断到一半（无报错）。

### 解决方案：分块写

```text
1. Write 覆盖文件：头部 + ASR 表 + 前 3 节，末尾带唯一锚点 <!-- APPEND_MARKER_1 -->

2. Edit 把锚点替换为"中段 + 下一个锚点"
   <!-- APPEND_MARKER_1 --> → <中段内容>\n<!-- APPEND_MARKER_2 -->

3. 重复直到所有小节写入

4. 最后 Edit 把末尾锚点替换为"附录 + 结尾"
```

锚点规则：

- 唯一字符串（不与正文冲突）：`<!-- APPEND_MARKER_N -->`
- 收尾时锚点必须**全部清掉**（用 grep 验证）

```bash
grep -c "APPEND_MARKER" "<场次目录>/01_清洗稿.md"   # 应 = 0
```

## ASR 订正对照表（必须放 01 头部）

格式：`| 原词（ASR） | 还原 | 说明 |`

**机制**：订正只做能 100% 确定的；不确定的标 `[ASR/存疑]`。**绝不臆造**——这是忠实原则的核心。词表来源优先级：**项目词表文件**（`init_project.py` 生成的 `<项目根>/_词表.md`；本项目可能另有位置，见项目 CLAUDE.md）> 本场头部已积累条目 > 现场判断。本场新订正的跨场可复用条目，收尾时回填项目词表（见 `references/07`）。

示例（演示格式，实际按本场遇到的项目填写）：

| 原词 | 还原 | 说明 |
|---|---|---|
| 某大模型产品名的同音错字 | 标准产品名 | 按上下文确定时还原 |
| 私董会类行业术语的误听 | 标准术语 | 误听常见于口音 |
| 疑似产品代号但无法确认 | `[ASR/存疑]` | 疑为某类工具，不强行还原 |

**称呼异常类**（说话人识别相关）：如某说话人自称了别人的名字、称呼与时间线矛盾——登记对照表并注明「口误/存疑」，时间线必查。

## 边缘类型规范

### 英文场

- **ASR 机械复制段整段剔除**：语气词、人名连刷数十次这类，剔除并登记进附录 D 忠实性说明
- **中英混转段原样保留**：ASR 把英语写成中文字词时只做对照表登记；**只有 100% 确定的才订正**
- **破碎句不臆造修复**：宁可保留破碎原样标 `[ASR/存疑]`，英文场的「不臆造」比中文场更严

### 屏幕级操作段

投屏演示/实操排障段不逐键还原，紧缩为「关键节点 + 结果」，头部忠实性说明登记紧缩依据。

### 特长场（>4h）

先探测录音空档判断「连续单场 vs 多场拼接」；确需拆窗清洗时每窗口独立编号，防 02/08 引用跨窗错位。
