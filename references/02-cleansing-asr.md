# 阶段 ② 清洗 + ASR 订正

## 目标

把 ASR 转写稿整理成**可读、可查、可作为后续模块素材源头**的清洗稿。

## 两种粒度（让用户选或自评）

| 粒度 | 回合数 | 适用 |
|---|---|---|
| **紧缩版** | 30–50 回合 | 用户要快速回顾；时间紧；后续可展开 |
| **逐回合还原版** | 150–700 回合 | 用户要忠实对话流；作为完整素材；后续做洞察卡片 |

08-09 场选择逐回合版（697 回合）。用户偏好：**默认逐回合还原**。

## 清洗原则（4 条，缺一不可）

1. **回合合并**：同一说话人连续的纯口水碎片合并为一个回合，保留首时间戳
2. **去口水**：删"嗯/啊/对对对/那个那个/就是就是/哈哈"等无意义重复；保留语气词当承载态度时
3. **补标点、理语序**，**不改原意、不改措辞**
4. **ASR 订正**：能确定的还原（见对照表），不确定的标 `[ASR/存疑]`，**不臆造**

金句原话一字不改——这是最高的忠实原则。

## ⚠️ 致命陷阱 P2：漏写右 `】`

`Write` 工具批量写回合格式时极易漏 `】`，写成：

```markdown
**【Harry** [00:00:39] 你还要解释……
```

**正确格式必须是**：

```markdown
**【Harry】** [00:00:39] 你还要解释……
```

漏 `】` → 渲染器识别不了 → **整篇金句格式失效** → HTML 里没有可点击金句卡。

### 检测（每段交付前必跑）

```bash
# 应输出 0
grep -cE '^\*\*【[^】]*\*\* \[' "<场次目录>/01_清洗稿.md"
```

08-09 场漏了 666 行，全靠这个命令抓到。

### 修复（一行 sed）

```bash
# macOS（sed -i ''）
sed -i '' -E 's/^\*\*【(人名1|人名2|人名3|人名4)\*\* /**【\1】** /' "<场次目录>/01_清洗稿.md"

# Linux（sed -i）
sed -i -E 's/^\*\*【(人名1|人名2|人名3|人名4)\*\* /**【\1】** /' "<场次目录>/01_清洗稿.md"
```

⚠️ 模式只匹配行首 `**【人名** `（缺 `】` 且缺第二个 `**`），不会误伤正确的 `**【人名】** `。

### 修复后再跑一次

```bash
grep -cE '^\*\*【[^】]*\*\* \[' "<场次目录>/01_清洗稿.md"   # 应 = 0
grep -cE '^\*\*【(郭磊|Harry|郭志梁|夏老师)】\*\* \[' "<场次目录>/01_清洗稿.md"   # 应 > 0
```

## ⚠️ 致命陷阱 P7：Write 超长截断

`Write` 一次写超大文件（> 5 万字节或含大量特殊字符）会被截断到一半。

### 解决方案：分块写

```python
# 伪代码
1. Write 覆盖文件：头部 + ASR 表 + 前 3 节，带唯一锚点
   <!-- APPEND_MARKER_1 -->

2. Edit 把锚点替换为"中段 + 下一个锚点"
   <!-- APPEND_MARKER_1 --> → <中段内容>\n<!-- APPEND_MARKER_2 -->

3. 重复直到所有小节写入

4. 最后 Edit 把末尾锚点替换为"附录 + 结尾"
```

锚点选择：

- 唯一字符串（不与正文冲突）：`<!-- APPEND_MARKER_N -->`
- 文件末尾的 `<!-- APPEND_MARKER_N -->` 必须**全部清掉**（用 grep 验证）

```bash
grep -c "APPEND_MARKER" "<场次目录>/01_清洗稿.md"   # 应 = 0
```
