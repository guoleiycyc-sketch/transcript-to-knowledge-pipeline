# 阶段 ④ HTML 组装

## 渲染行为速览（改动渲染器前必读）

**页面结构顺序**：`阅读协议横幅 → ① 执行摘要卡（brief，可折叠 details 默认展开：局势+决策要点+待办表精简+风险行+「跳过摘要」锚）→ ② 分段速览（digest：每段一行卡=段号+标题+## 摘要+「展开该段」；母题/洞察胶囊/战略链接）→ 人物卡 → 议题地图 → 洞察卡 → 方法论 → 行动清单 → 术语表 → 数据速查 → 主题分段 seg1-N（全文层垫底）`。

有②层时不再渲染自动总览（定制 `00_总览.md` 与无②层老场除外）；**无 00_执行摘要 的场整块三层导航不渲染**（页面结构与旧版一致）。

**层间锚点（摘要层→③层）**：模块容器用稳定 id（#people/#map/#insights/#method/#strategy/#glossary/#data/#segN/#insight-N）；①卡内人名与待办 Owner 列自动链接 #people、卡N→#insight-N、圈号①-⑳ inline_fmt 原生链接 #segN、手写 `[文本](#锚点)` 也走下潜链接。

**折叠策略（结论展开、过程折叠）**：展开=①摘要卡/②速览行/洞察卡/方法论卡/数据表；折叠=段「②详析」（details + JS 锚点跳入自动展开，折叠不吞跳转）/段原文节选/人物详细卡/命中校验（质检数据）。

**图形化**：``` 代码块先过 `try_render_graph` 定向解析——①分层带（层名行+圈号条目，读「—— 绿」颜色意图）②线路流（→≥2）；失败回退深色终端卡。正文圈号①-⑳ 全局渲染为可点段链接，「 → 」渲染为彩色箭头。

**渲染自检**（render_pack 末尾自动跑）：副标题星号泄漏/旧对比色残留/死类复活/重复注/锚点有效性/②层字数。改渲染器后另跑 `scripts/regression_check.py`（自构造样板断言），变更记 CHANGELOG 并升 SKILL.md version。

## 一条命令出 HTML

```bash
python3 <skill目录>/scripts/render_pack.py <场次目录>
# 可选：--brand "显示名"（不带则用场次目录名作标题）
# 分享版：--share [--alias "陈岸→A,林一→B"]
#   生成 <场次名>_分享版.html：剔除价格/健康级引语行（词表与 extract_atoms 同源）+
#   可选人名化名替换（全 md 生效：金句/人物卡/Owner 一并换）；临时副本上处理，原稿不动。
#   注意：06 数据表与叙述文字未过滤——外发前人工过一遍。
```

**不要试图手写 HTML**——`render_pack.py` 从 md 文件自动提取配置，生成 `<场次目录名>.html`（自包含 CSS/JS 内联，双击即开，无外部依赖）。终端会打印提取到的段数/人数/洞察数/方法论数/术语数，方便核对。

## render_pack 自动提取了什么（无需手写配置）

| 项 | 来源 |
|---|---|
| 段标题 / 副标题 | 02/第N段 的 `# 第N段 · 标题` + `> 时段：` |
| 人物 / 发言量 / 一句话标签 | 05 的 `## 人名` + `约 XX%` + `**背景与立场**：` |
| 母题 | 07 的 `**母题**：` |
| 洞察卡数 | 08 的 `^## 卡 \d+` |
| 方法论卡数 | 03 的 `^## \d+\.` |
| 术语条数 | 04 的 `^### ` |
| 是否有行动清单 | 09 文件是否存在 |
| 侧栏导航 / 段名 / 各模块计数 | 全部自动生成 |

只要 md 按 `references/03` 的契约写，就零配置出 HTML。

## 交互能力的真实边界（别对外夸大）

- **金句卡点击复制**：始终有效（clipboard API + execCommand 兜底）
- **时间戳跳转**：跳到**页面内**对应时间戳的行（`#ts-HH-MM-SS`，来自 02 原文节选区）；点击后平滑滚动+临时高亮
- 01 清洗稿默认**不渲染进 HTML**（避免文件超大）——所以金句在页面内无对应原文行时，时间戳点击无反应，但复制不受影响。要启用「跳全文」需把清洗稿渲染成折叠 transcript 段（render_pack 默认不做）
- 全文搜索高亮、表格排序、深浅主题：正常可用

## 定制总览页（可选）

默认总览页是自动骨架。想要更丰富的总览（背景、与上一场的关系、贯穿主题），写 `00_总览.md` 放场次目录，render_pack 用它的内容作总览页。

## 深度定制（monkey-patch 模式）

日常用法就是 `render_pack.py` 一键出 HTML。只有要**内容特定的花式可视化**（手画三层信息图、维度泳道、量级条）时才下场自己写：

```python
# 在自己的脚本里（如场次目录内的 build_custom.py）：
import sys
sys.path.insert(0, "<skill目录>/scripts")
import build_html as B

B.render_map = my_render_map          # 覆盖某渲染函数
B.render_insight_map = my_render_map2 # 只覆盖差异点，CSS/JS/通用渲染复用母版
```

**不要把渲染器代码复制到场次的产物里改**——CSS/JS 重复维护，每改一处要同步多场。母版 `build_html.py` 约 2400 行（含完整 CSS/JS），一般不用通读，遇到渲染问题再 grep 定位。

**验证方法**：grep 上一场人名/段名，区分"残留 bug" vs "合法跨场呼应内容"。

## 已知坑（HTML 渲染相关）

完整坑库见 `references/06-pitfalls.md`。渲染特有高频坑：

| 坑 | 原因 |
|---|---|
| 金句全是普通文字 | 漏 `】` 或时间戳格式错 |
| 侧边栏段顺序乱 / 提取段数为 0 | 02 文件名 N 不连续、首行不是 `# 第N段 · ` |
| 人物卡进度条 0 | 漏写 `约 XX%` |
| 议题地图变成普通段落 | 没包 ``` 代码块 |
| 洞察卡只有核心、没启示/反方 | 字段头写错（渲染器静默不识别） |
| 时间戳写成 [MM:SS] 短格式 | 渲染契约要求 [HH:MM:SS] 全格式；短格式还会被引文校验报硬伤 |
| 不带 `--brand` 时标题是目录名 | 想自定义加 `--brand "..."` |
| 改 CSS 作用域引入层叠回归 | 同特异性后者覆盖，机械自检查不出——改前列出所有会命中的容器，改后人眼看打样页 |
