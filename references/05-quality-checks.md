# 发布前 6 次必查

每场知识包交付前**必须**按顺序跑完这 6 次检查。任意一次不过，**不要交付**——回去修。

## 检查 1：说话人一致性（最高优先级）

**问题**：上次（08-09 场）连续判错两次说话人——把说话人3 当夏老师、把郭志梁当隐形人。

### 检测命令

```bash
cd "<场次目录>"

# 1.1 残缺标签（漏 】）—— 应 = 0
grep -cE '^\*\*【[^】]*\*\* \[' 01_清洗稿.md

# 1.2 各说话人回合数 —— 应与映射一致
echo "郭磊: $(grep -cE '^\*\*【郭磊】\*\* \[' 01_清洗稿.md)"
echo "Harry: $(grep -cE '^\*\*【Harry】\*\* \[' 01_清洗稿.md)"
echo "郭志梁: $(grep -cE '^\*\*【郭志梁】\*\* \[' 01_清洗稿.md)"
# ……按你这场的人物加

# 1.3 残留未替换的说话人标签（ASR 原标签如 "说话人2" "说话人3"）—— 正文应 = 0
grep -E '^\*\*【说话人[23]' 01_清洗稿.md
grep -cE '^\*\*【说话人' 01_清洗稿.md
```

### 自查

- 主导角色（用户明确告诉你的）= 说话人回合数最多的人之一？
- 各说话人指纹（角色、内容）是否与头部映射声明一致？
- 时间线：X 在 `[HH:MM:SS]` 才到场，X 之前被 ASR 标 X 的回合是否矛盾？

## 检查 2：ASR 残留

**问题**：脏数据没清干净，订正对照表没覆盖。

```bash
# 2.1 已知 ASR 错字残留（按这场实际遇到的项目）—— 应 = 0
grep -cE "K三|质朴[^a-z]|单独[^a-zA-Z]tree[^a-zA-Z]|workbody|沃克波队|我哥 body|司总会|四总会|巨身智能|m MPV" 01_清洗稿.md

# 2.2 所有 [ASR/存疑] 项数（合理；过多说明清得不够）
grep -c "\[ASR/存疑\]" 01_清洗稿.md

# 2.3 对照表里每项在正文里要么 0 次、要么都加了 [ASR/存疑]
```

**对照表与正文必须一致**：对照表里有 `[ASR/存疑]` 的项，正文里用 `[ASR/存疑]` 标注；不在表里的常见 ASR 错字不应该出现在正文。

## 检查 3：金句格式（最容易出 bug 的地方）

**问题**：漏 `】`、时间戳格式错、姓名漏 `【】`——整篇金句卡失效。

```bash
# 3.1 残缺格式 —— 应 = 0
grep -cE '^\*\*【[^】]*\*\* \[' 01_清洗稿.md

# 3.2 时间戳格式（HH:MM:SS 或 MM:SS）
grep -cE '\*\*【[^】]+】\*\* \[[0-9]{2}:[0-9]{2}(:[0-9]{2})?\]' 01_清洗稿.md

# 3.3 附录 B 金句速查格式（应 = 8 条左右，编号 + **【...】** [ts] ...）
grep -cE "^[0-9]+\. \*\*【" 01_清洗稿.md
grep -cE "^[0-9]+\. \*\*【" README.md

# 3.4 锚点残留 —— 应 = 0
grep -c "APPEND_MARKER" 01_清洗稿.md

# 3.5 清洗稿末尾无孤立锚点
tail -5 01_清洗稿.md
```

## 检查 4：结构完整性（9 模块）

```bash
cd "<场次目录>"

# 4.1 必备文件存在
for f in 01_清洗稿.md 02_主题整理 03_方法论清单.md 04_术语表.md \
         05_人物角色卡.md 06_关键数据速查.md 07_议题关联地图.md \
         08_洞察卡片.md README.md; do
  [ -e "$f" ] && echo "OK $f" || echo "MISSING $f"
done

# 4.2 02 主题整理文件名连续
ls 02_主题整理/ | grep -E '^第[0-9]+段'

# 4.3 段标题首行格式
grep -E '^# 第[0-9]+段 · ' 02_主题整理/*.md | head -20

# 4.4 人物卡标记完整
for person in $(grep -E '^## ' 05_人物角色卡.md | sed 's/## //'); do
  echo "$person:"
  awk "/^## ${person}\$/,/^## /" 05_人物角色卡.md | grep -E '\*\*背景与立场\*\*|约 [0-9]+%'
done

# 4.5 洞察卡有反方
grep -c "^\*\*反方\*\*" 08_洞察卡片.md   # 应 = 卡片数

# 4.6 议题地图有母题 + 代码块
grep -E '^\*\*母题\*\*' 07_议题关联地图.md
awk '/^```$/ {c++; if (c>=2) exit}' 07_议题关联地图.md   # 至少有一个代码块
```

## 你可能没想到的地方

最后特别说明几个**本次实践中浮出来的、容易被忽视的检查项**：

### ① 说话人识别不能"先入为主"地锁定

第一次回答用户"说话人2 是谁"时，**绝不能顺便假设说话人3 是什么人**。本次教训：

> 我假设"说话人3 = 夏老师" → 用户首次确认了"说话人2=Harry"，没纠正我的假设 → 几小时后用户主动纠正（"主导商业规划的是郭志梁"）→ 我才发现整篇说话人标错

**永远保留追问的余地**。不要一次问完所有映射。

### ② "用户确认过"≠"正确"

用户的首次回答可能基于不完整信息（只看了头部几段、记不清谁是谁）。**AI 不能把用户首次回答当成绝对真理锁死**。

任何发现矛盾（如"主导商业规划的 X"对不上当前映射），立即回原文复核，而不是猜测或忽略。

### ③ 大文件必须分块写

`Write` 工具一次写超大文件会截断（> 5 万字节 + 大量特殊字符极易出问题）。**永远分块**：Write 头部 → Edit 追加中段（用唯一锚点）→ 末尾去锚。

### ④ 写完立刻 grep 自检

不要"写完就觉得对了"。立刻跑 `grep -cE '^\*\*【[^】]*\*\* \['`——这是发现 P2 漏 `】` 陷阱的唯一手段。

08-09 场 666 行漏了，全靠这个 grep 抓到。

### ⑤ 跨场复用要"monkey-patch 不要复制"

不要把上一场的 HTML 生成代码复制过来改——跨场共享渲染器（CSS/JS/通用渲染），用 monkey-patch 覆盖差异点。详见 `references/04-html-assembly.md`。

### ⑥ 陷阱库要持续累积

每次新场次执行，pitfalls 库加新坑。`references/06-pitfalls.md` 是活文档。
