# 批量清洗模式（轻量模型子代理流水线）

> 适用：几十场存量的批量清洗。2026-08-28~29 用此模式清洗 **159 场**、常规未洗场次清零，入库 79 场主对话质检零硬伤。单场精洗不走本流程。

## 架构：主对话指挥 +轻量模型子代理执行 + 主对话质检

| 角色 | 职责 |
|---|---|
| 主对话 | 派发清单、逐场质检、索引打 ✅、异常处理、全局层同步 |
|轻量模型子代理（低成本快速模型档位） | 读原始转写 → 按体例产出 01 清洗稿（轻档加 00） |

分派粒度：按目录分批（如「05 商务线 30 场」一批），每批一个子代理顺序处理或多个子代理并行。**派发前先查来源 `_索引.md` 的 ✅ 标记与既有场次目录，防重复清洗**（实战拦截 4 次）。

## 子代理派发模板（输出纪律是生死线）

> 无纪律批次 5/6 因单次输出超 32K 被静默终止；带纪律后零失败（P28）。

```
任务：清洗 <原始转写路径> → 产出 <场次目录>/01_清洗稿.md（+00_执行摘要）
体例：transcript-to-knowledge-pipeline skill 的 references/02——
      头部双源字段 / 回合合并 / ASR 对照表 / §N 小节【业务】【闲聊】/ 附录 A-D
说话人：按 references/01 角色指纹法；无法确定的标 [存疑] 并在头部列出，不猜

⚠️ 输出纪律（违反即终止）：
1. 中间回复 ≤2 句（只报进度，不复述内容）
2. 每次写文件 ≤80 行（特长场分块 ≤120 行/次），长稿分块 Write + Edit 锚点追加
3. 长内容只进文件，不在对话输出
4. 金句原话一字不改；ASR 不臆造
```

**子代理产出的引文不可信**：02/08 里代理报的金句时间戳可能错（客户戊场实测 [00:51:33] 被错报两处）——凡有 02/05/08 的场次，引文必须回 01 grep 重新定位，verify_quotes 兜底。

## 质检分工（主对话逐场）

1. `bash scripts/pipeline_check.sh <场次目录>` —— 说话人一致性 / 格式 / 结构
2. `python3 scripts/verify_quotes.py <场次目录>` —— 有 02/05/08 的场次（硬伤 exit 1）
3. 抽查头部映射 + 说话人存疑项登记
4. 来源 `_索引.md` 对应行打 ✅

## 已知运营事件与处理

| 事件 | 处理 |
|---|---|
| 模型内容审查拦截（某零售企业分红案例/某大厂出海分享/共创社区类，涉资本政治内容） |轻量模型无法处理 → 转主对话清洗，或用户裁决放弃留档 |
| 同源双稿（VokeBody / WorkBody_08-19 等） | 择一清洗，另一份索引注「同源并档」 |
| 特长场（03-25 Z1装机 7h58m） | 先探测空档判连续/拼接，拆窗口清洗、窗口独立编号 |
| 说话人存疑累积 | 汇总到 `_全局资产/待用户复核清单.md`，收尾批量请用户裁决（先例：38 项存量单日裁决 26 项） |
| 同日多切片（某次旅行录音 6 切片） | 并档为一场，索引注明 |

## 批量收尾（全部完成后）

1. 存疑清单批量裁决 → 子代理并行订正场次产物（先例 3 子代理 ~30 文件）+ 主对话订正全局层（词表裁决批次区块/干系人/决策日志/两索引）
2. `extract_atoms.py <项目根>`（递归版）重跑 + `render_views.py` 三视图刷新
3. wiki-sync + openwiki 增量（如项目配置了知识库）
